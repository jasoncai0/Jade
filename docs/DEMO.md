# Five-minute demo

This script demonstrates the parts that matter: real local execution, a ten-phase
observable loop, tool/skill discovery, and a compile-failure repair.

## 0. Preflight

```bash
cd java-coding-agent
java -version
mvn -version
./run.sh --check
```

Expected: `javac 21+`, Maven, 10 tools, 3 skills, writable workspace. The API
key line may say `MISSING`; that is expected until step 1.

## 1. Configure the key

```bash
cp .env.example .env
$EDITOR .env
```

Set:

```
DEEPSEEK_API_KEY=sk-...
```

Then verify the API path:

```bash
./run.sh --ping
```

Expected: `pong` or a short model reply. A 401 means the key is wrong; a
timeout means the network or base URL is wrong.

## 2. Start the console

```bash
./run.sh
```

Open <http://127.0.0.1:8080>. The top-right key pill should say `key ready`.
The empty state shows:

- 10 built-in tools
- 3 discovered skills
- 10 phases per turn
- 1 isolated workspace per run

Click `How it works`, `Skills`, and `Tools` to show the three discovery
surfaces. The Skills dialog lists the actual files discovered from `skills/`.

## 3. Build something real

Click the `Prime CLI` example, or paste:

```
Create a Java CLI named PrimeCLI that prints the first 15 prime numbers, one
per line. Compile it and run it to prove the output is correct.
```

Press `Start agent`. Watch:

1. The plan appears in the right rail.
2. The phase rail lights through Intake → Checkpoint for each model turn.
3. The tool card shows `write_file` arguments and the real write result.
4. A second tool card shows `compile_java` / `run_java` output.
5. The verification panel turns green with the exact `javac` command.
6. The run ends `SUCCEEDED`; the workspace panel lists `src/Main.java`.
7. Stop the process, run `./run.sh` again, and reload the page. The left rail
   still lists the session; select it and the plan, trace, files, and final
   answer replay from `.agent/`.

Each model call also adds a collapsed `LLM REQUEST` card to the trace. Click
`request body` to inspect the exact JSON sent to DeepSeek: model, messages,
tool schemas, temperature, and token limits. It is collapsed by default so the
conversation stays readable. The body never contains the API key; authorization
travels in an HTTP header.

Click the file to preview it. The transcript path in the inspector points at the
artifact on disk; open:

```bash
open agent-workspaces/run-*/src/Main.java
```

Each run has its own directory. The transcript is at
`agent-workspaces/run-*/.agent/transcript.json`; the final answer is in
`.agent/final.md`.

## 4. Show the repair loop

Start a second run:

```
Create a Java program with one deliberate compile error, run javac to show the
error, then fix it and prove the corrected program runs.
```

Expected events:

- a collapsed `LLM REQUEST` card for every model call; expand one to show the
  exact JSON body sent to DeepSeek
- a red/amber verification card with the real compiler diagnostic
- a user-style feedback message in the transcript
- another `write_file` / `edit_file` call
- a later green verification card and a run with status `SUCCEEDED`

This is the important difference from a chat demo: the failure is generated by
`javac`, not by the model's imagination, and the success is produced by a real
`java` process.

## 5. Show discovery

With the server running, inspect the API:

```bash
curl -s http://127.0.0.1:8080/api/tools | python3 -m json.tool
curl -s http://127.0.0.1:8080/api/skills | python3 -m json.tool
```

The tools response includes JSON schemas; the skills response includes the
frontmatter and relative path. To prove dynamic tool discovery, see the
`ServiceLoader` section in [README.md](../README.md) and the provider test in
`src/test/java/io/github/jasoncai0/agent/tool/ToolRegistryTest.java`.

To prove skill discovery, add a directory:

```bash
mkdir -p skills/hello
cat > skills/hello/SKILL.md <<'EOF'
---
name: hello
description: Say hello in a deterministic way.
tags: [hello, demo]
triggers: [hello]
---
# Hello

Print exactly `hello-skill` and verify it.
EOF
```

Restart the server; `GET /api/skills` now returns four skills. Remove the
directory to restore the demo state.

## 6. Headless fallback

If the browser is inconvenient:

```bash
./run.sh --task "Create a Java CLI that prints hello-jade, compile and run it" \
  --workspace hello-demo
```

Expected console output includes the phase lines, tool output, verification
PASS, the run id, token usage, and the transcript path. The process exits `0`
only for `SUCCEEDED`.

## 7. Cleanup

Stop the server with Ctrl-C. Remove demo runs if desired:

```bash
rm -rf agent-workspaces/run-*
```

Do not commit `.env`; it is ignored. The jar is at `target/coding-agent.jar`.

## What to point out in a review

- The ten phases are emitted as real events, not labels painted by the UI.
- Tool calls are executed by the server and the results are fed back verbatim.
- `javac` and `java` are real subprocesses; the verification card contains their
  command and output.
- Skills are discovered from disk and selected by a deterministic score.
- External tools use the standard `ServiceLoader` SPI.
- This is a local demo; the HTTP server is unauthenticated and the shell guard
  is not a sandbox. Say that explicitly.
